# OR Midterm Project

This repository contains the IP solver, heuristic solvers, public instances, generated test data, and benchmark scripts for the car relocation/order acceptance problem.

## Environment

Use Python 3.12. The project was developed with:

```bash
pip install -r requirements.txt
```


## Repository Layout

| Path | Purpose |
| --- | --- |
| `algorithm_module.py` | Algo1 greedy insertion solver. |
| `heuristic_algo2.py` | Algo2 order-node DP trajectory solver. |
| `heuristic_algo3.py` | Algo3 Algo1 plus local repair solver. |
| `heuristic_algo4.py` | Algo4 Algo1 plus local IP repair solver. |
| `ip_solver.py` | Integer programming solver for public/small instances. |
| `mtp_common.py` | Shared parser, data model, and utilities. |
| `data/` | Public instances, S1-S14 generated instances, and the generator script. |
| `experiments/` | Legacy benchmark scripts, generated smoke tests, and CSV results. |
| `docs/approach.md` | Algorithm explanation, IP model summary, and time complexity. |
| `reference/` | Project statement and related reference PDFs. |

## Generate Test Data

The experiment data in this branch follows the 14-scenario design documented in
`docs/experiment.md`. Instances are generated by `data/generate_code.py` and are
stored under `data/exp_instances/`.

Generate the full dataset:

```bash
cd data
python generate_code.py
```

This creates:

```text
data/exp_instances/
  S1/S1_inst_01.txt ... S1_inst_30.txt
  ...
  S14/S14_inst_01.txt ... S14_inst_30.txt
```

Important: `generate_code.py` deletes and recreates `exp_instances` in the
current working directory. Run it from `data/` to regenerate
`data/exp_instances`; running it from the repository root would create
`./exp_instances` instead.

The generator uses these scenario settings:

| Scenario | Focus | Ratio | Level | Station | Time | Budget |
| --- | --- | ---: | --- | --- | --- | --- |
| S1 | Baseline | 1.0 | random | random | random | 1,000,000 |
| S2 | Very high load | 10.0 | random | random | random | 1,000,000 |
| S3 | Low load | 0.333 | random | random | random | 1,000,000 |
| S4 | High load | 3.0 | random | random | random | 1,000,000 |
| S5 | Level mismatch | 1.0 | 8:2 skew | random | random | 1,000,000 |
| S6 | Forced relocation | 1.0 | random | odd/even | random | 300 * n_D |
| S7 | Hub effect, 1 group | 1.0 | random | hub_1G | random | 300 * n_D |
| S8 | Hub effect, 2 groups | 1.0 | random | hub_2G | random | 300 * n_D |
| S9 | Weekend peaks | 1.0 | random | random | weekend | 1,000,000 |
| S10 | Single burst | 1.0 | random | random | peak_1 | 1,000,000 |
| S11 | Three bursts | 1.0 | random | random | peak_3 | 1,000,000 |
| S12 | Zero budget | 1.0 | random | random | random | 0 |
| S13 | Tight budget | 1.0 | random | random | random | 30 * n_D |
| S14 | Moderate budget | 1.0 | random | random | random | 300 * n_D |

For each generated instance, `n_S=100`, `n_L=10`, `n_D` is sampled from 7 to
100, `n_C=80` for S2 and S4 and `n_C=100` otherwise, and `n_K=int(n_C * ratio)`.

## Run Benchmarks

### Exp Instance Benchmark (S1-S14)

This branch contains the benchmark run for `data/exp_instances/S1` to `S14`.
Each scenario has 30 generated `.txt` instances, so the full run covers 420
instances.

The benchmark CSVs compare `ip_solver` with `algo1` to `algo5`. `algo2`,
`algo3`, and `algo4` were run with a 10 second time limit on the remote
machine `b13902103@ws6` under `/tmp2/b13902103/OR_Midterm_project` using the
project `.venv`.

Recommended commands:

```bash
# IP optimal plans and per-instance runtime logs.
python run_all_ip_solver.py --root data/exp_instances

# Algo1 and Algo5, plus importing IP plan metrics into benchmark_results.csv.
python run_algorithm_benchmarks.py \
  --root data/exp_instances \
  ./algo1.py ./algo5.py

# Algo2, Algo3, Algo4, and AlgoUnion with TL=10s, parallelized by scenario.
python run_algo_parallel.py \
  --root data/exp_instances \
  --max-seconds 10 \
  --jobs 14

# Scenario-level summaries, detail table, optimal-gap table, and SVG chart.
python summarize_benchmarks.py \
  --root data/exp_instances \
  --out-dir data/exp_instances/summary
```

Generated outputs:

| Path | Content |
| --- | --- |
| `data/exp_instances/S*/plan/*_optimal_plan.txt` | IP solver plan for each instance. |
| `data/exp_instances/S*/run_time.csv` | IP solver runtime and objective/profit by instance. |
| `data/exp_instances/S*/benchmark_results.csv` | One row per `(instance, algorithm)` for `ip_solver` and `algo1`-`algo5`; 180 rows per scenario plus header. |
| `data/exp_instances/summary/scenario_summary.csv` | Scenario-level average profit, gap, moving time, execution time, wins, and ties. |
| `data/exp_instances/summary/instance_gap_detail.csv` | Per-instance gap detail for every heuristic result; 2100 rows plus header. |
| `data/exp_instances/summary/optimal_gap_table.csv` | Compact table of average optimal gap for `algo1`-`algo5` by scenario. |
| `data/exp_instances/summary/scenario_algo_comparison.svg` | Bar chart comparing average optimal gap and head-to-head wins. |

The optimal gap is defined as:

```text
optimal_gap = (ip_profit - algorithm_profit) / abs(ip_profit)
```

Lower is better. A gap of `0` means the algorithm matched the IP value on
average for that scenario. Negative gaps should not appear after the time
origin fix in `mtp_common.py`; seeing one usually means the parser and solver
are using inconsistent planning horizons.
